# A2f-2 preregistration addendum 1 — correct `.7` midpoint resolution

This addendum is registered before the corrective run and before A2f-3 preregistration. A review while preparing the next-stage design found an arithmetic error in the numeric resolution of one frozen cell: the original preregistration correctly specified `K=round(U/sqrt(m_min*m_max))`, but listed `K=16` for F=120, U=84, `m_min=84/37`, and `m_max=28`. Applying that formula gives `round(84/sqrt((84/37)*28)) = 11`, not 16. The initially tested K=16 cell is retained as a documented preregistration deviation and is excluded from the corrected gate; it is not silently relabeled.

The corrected replacement cell is life=.7, F=120, U=84, K=11, mean-up `84/11 = 7.636363636...` frames. No other cell changes. Run seeds 42..241 (200), pathPersistency .75, exact U/K requirement 200/200; draw-category multinomial Monte Carlo chi-square with 99,999 null draws, diagnostic RNG seed `20261010`, must have p>=.01; each operation <=60 s without retry. Save per-seed realized U/K/down-run count/time, per-trace config plus source hashes. For the final corrected gate, combine the 11 unaffected cells from the original preregistered grid with this 200-trace replacement; exclude the erroneous K=16 cell.

All other A2f-2 gates remain unchanged: 81 F=8 exact support pairs, 15 stored-trace regressions per comparison, 27 boundary invalid-K requests plus one mean-derived invalid request, and clean-copy dry-run. Existing original outputs and hashes remain immutable evidence of the deviation. The corrected artifact is stored separately in `results/correction_v1/`; original results are not overwritten.
