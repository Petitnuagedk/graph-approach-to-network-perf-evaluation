## Frozen implementation requirements

- All A3 behavior is opt-in. With A3 flags absent, retain current flow selection, callbacks, `trace_replay_results.csv` schema/order, legacy output behavior, and existing diagnostics behavior. Place new per-flow/node diagnostics in separate files so the existing results CSV is not expanded or reordered.
- In instrumentation mode, the first explicit `--flows` entry is the designated probe flow. Its unordered pair is excluded from background-pair selection. Add exactly `round(phi*N*(N-1)/2)` unordered background pairs, using C++ `std::llround` (half away from zero); reject a request whose count exceeds the available non-probe unordered pairs. Enumerate candidates lexicographically; shuffle with `std::mt19937_64(flowSeed)` and `std::shuffle`; take the first K; choose each direction from the next RNG bit. Use a distinct `--flowSeed` stream (default 9001, never reused as the ns-3 `--seed`). For n total flows in final order (probe first), flow i starts at `warmup_effective + 0.1 + i/n` seconds, for i=0..n−1. Thus all clients are staggered within the first second.
- `flows.csv` records each flow's id, endpoints, probe flag, static-skeleton hop distance, offered UDP-client Tx packets, delivered unique sink packets, median and p95 end-to-end delay, first delivered probe time, and probe convergence time. Also write static-skeleton all-pairs hop distances. Define the static skeleton as the union of links present in any input frame; calculate unweighted shortest paths on this graph. Unreachable distances are `NA`.
- `node_diagnostics.csv` reports per-node routing-control Tx packet/byte counts by the existing message-type parser; data packets at IPv4 `UnicastForward` (only app-port UDP, excluding originated and local-delivery packets); MAC data-failure/retry callbacks (`MacTxDataFailed`), final data failures (`MacTxFinalDataFailed`), existing MAC Tx/queue drops; and PHY Rx drops by raw `WifiPhyRxfailureReason` plus a conservative reason classification. Classify a drop as below-sensitivity only when the frame's MAC sender can be mapped and trace-model expected receive power is below the configured sensitivity. Classify as collision/interference only when expected power is at/above sensitivity and the reason is one of `RXING`, `BUSY_DECODING_PREAMBLE`, `PREAMBLE_DETECT_FAILURE`, `L_SIG_FAILURE`, `HT_SIG_FAILURE`, `SIG_A_FAILURE`, `SIG_B_FAILURE`, `U_SIG_FAILURE`, `EHT_SIG_FAILURE`, `PREAMBLE_DETECTION_PACKET_SWITCH`, `FRAME_CAPTURE_PACKET_SWITCH`, `OBSS_PD_CCA_RESET`, or `DMG_HEADER_FAILURE`. Preserve an `other_unclassified` category whenever source/power/reason is ambiguous; retain the raw enum for every event. The existing `dumpRoutes` option remains the opt-in 1 Hz route-table dump.
- Probe convergence: record first successfully delivered probe packet. Evaluate trailing `[t−10,t]` windows at all Tx/Rx event times and their 10-second expiry times, from the first full window through simulation end. Window PDR is unique probe Rx events divided by probe Tx events in that same wall-clock window; empty windows fail. Convergence is the earliest window-end `t` for which this and every later full window through the end has PDR >=.99. If no such point exists, write `NaN`. T3 will test exact boundary/never-converges behavior.
- Use the IPv4 `UnicastForward` event as the forwarded-packet definition. Therefore the expected forwarded total for fully delivered flows is the delivered-router-forward total `sum_packets(max(static_hops-1,0))`; source-originated and destination-local-delivery events are excluded. Report undelivered packets separately. Do not equate this with link-layer transmissions or count link retransmissions as IP forwards.
