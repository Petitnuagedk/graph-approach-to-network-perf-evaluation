# A3b Step 1 — offline AODV forward-counter diagnosis

**Saved-run diagnosis: event attribution is undecidable.** A3 T1's `packet_diagnostics_aodv.csv` contains only aggregate packet/drop totals (391 Tx, 391 total/unique sink Rx, zero IP no-route/route-error drops); `packets_aodv.csv` and `times_aodv.csv` are application Tx/Rx events with sequence/time, not `UnicastForward` events. The node counter says 2 events at node 0, but the saved records provide no forwarding-event source/destination address, callback timestamp, packet/sequence identity, or packet UID. Therefore they cannot establish whether the two events were early route-discovery reinjections (H_a), later route-error/rediscovery reinjections (H_b), or another source (H_c).

The AODV mechanism makes H_a a concrete possibility, not an attribution: in ns-3 3.46.1 `src/aodv/model/aodv-routing-protocol.cc:446–456`, `RouteOutput()` sends no-valid-route traffic via loopback with a deferred-output tag; `:508–516` detects loopback input and queues it; `:2017–2036` later invokes the queued `UnicastForwardCallback` after setting the source to the selected route source and compensating TTL. Thus an originally local UDP datagram can reach IPv4's forwarding callback after route resolution. Source alone is insufficient to prove these two counter events followed that path. H_b and H_c likewise remain undecidable from saved events.

The exact trace is IPv4 `UnicastForward`: ns-3.46.1 `src/internet/model/ipv4-l3-protocol.cc:100–104` declares it; `:1025–1064` implements `IpForward()` and emits it at `:1064` before physical send. A3's `scratch/graph-run.cc:930–934` handler increments the A3 node counter for app-port UDP without checking whether source or destination is local to the counting node. A3b will therefore enable per-event logging for matching app UDP, including time, node, IP source/destination, UDP ports, `SeqTsHeader` sequence/timestamp when parseable, packet UID, local-address flags, and whether the amended predicate counts it. This log is diagnostic only; it will not selectively suppress AODV events.
