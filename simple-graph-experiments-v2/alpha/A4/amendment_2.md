## OLSR parser diagnosis and copy-only patch

`ControlMessageKind` removes IPv4/UDP then, whenever OLSR is active, assumes the UDP payload is an OLSR packet and calls `PeekHeader(MessageHeader)` after removing `PacketHeader`. `RecordControlTx` applies it to every non-app IPv4 Tx; there is no UDP-port-698 check or OLSR packet-length guard. The assertion requires the byte at the assumed first-message offset to be outside OLSR types 1–4. A valid two-message aggregate did **not** assert in the unit test; aggregation alone is not the demonstrated cause. A malformed two-message aggregate with first type 0 and a valid second TC message reproduced the exact `MessageHeader::Deserialize` SIGABRT, and the proposed raw-byte guard rejects it without deserialization. The actual offending run packet was not captured, so the real malformed/non-OLSR packet cause remains unproven.
